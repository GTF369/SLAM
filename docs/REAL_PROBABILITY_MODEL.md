# 真实眉形选择概率：开源模型边界与执行流程

## 目标变量先定义清楚

应用唯一能从顾客行为直接观察到的个体目标，是：**在这一次展示的自然款、柔和款、立体款三个候选中，顾客最终选择每一款的条件概率**。这三项概率针对当前三个候选，合计为 100%。它不是一个脱离顾客偏好、审美文化与候选集合的“客观眉形适配概率”，也不等于最终纹绣效果成功率。

“获得 4–5 分评价的概率”是另一个二分类目标，不能把它与“最终选中概率”混为一谈。应用只应在对应目标的模型通过校准和独立验证后显示百分比。

## 开源资料审查

- [DAM-Net](https://github.com/Dancingmader/DAM-Net) 是 MIT 代码许可证下的眉毛图像 matting 项目，README 列出 68 张带人工标注的真实眉图和 1,215 张未标注真实眉图。它解决的是眉区轮廓/alpha matting，不包含“同一顾客在三个眉形中选择哪一个”的标签，因此不能训练选择概率。
- [SCUT-FBP5500](https://github.com/HCIILAB/SCUT-FBP5500-Database-Release) 为整脸吸引力评分数据，官方使用条件限制为非商业学术研究。它不包含配对的三种眉形选择标签。仓库里的 ResNet 只能作为群体整脸审美参考，不是个体眉形适配概率。
- [MEBeauty](https://github.com/fbplab/MEBeauty-database) 包含整脸吸引力评分和个人偏好评分，官方发布条款也限制为非商业学术研究，且评分目标是整脸，不是眉形候选选择。
- 2023 年论文 [Eyebrow Shape Preference Across Age, Gender, and Self-reported Ethnic Group](https://pubmed.ncbi.nlm.nih.gov/36728068/) 报告 652 名受访者对同一主体的五种眉形编辑图进行排序。2025 年东亚眉形研究 [Ideal Eyebrows in East Asians](https://pubmed.ncbi.nlm.nih.gov/41068491/) 报告 513 人参与 AI 编辑眉形评分。公开可检索的信息报告总体研究发现，但未发现包含每张顾客脸、每个候选与逐个受访者选择标签的开放训练表。
- 因此，当前没有找到可合法直接接入且提供逐顾客候选选择标签的开源权重。把整脸吸引力分 softmax 成百分比会制造虚假的概率可信度，不能这样做。

## 应用里已经落实的数据采集方式

“记录三款眉形的真实反馈”一次采集整个候选集合。它要求自然、柔和、立体三款各有 1–5 分评价，再强制选择唯一最终候选。三行共享同一匿名顾客代码和会话 ID，并保存顾客实际看到的各候选参数、显示分数、当前已有概率（若存在）与群体审美分（若存在）。重复保存同一会话会替换旧三行，避免一个会话被计为两个样本。CSV 不包含人脸照片。

使用时应对同一顾客重复使用不含身份含义的随机代码，并先取得针对匿名特征、评价和选择标签的明确授权。不能将姓名、电话号码、预约编号写进代码字段。

## 训练真实条件选择概率

安装训练依赖：

```bash
python -m pip install -r ml/requirements.txt
```

将应用导出的 CSV 按匿名顾客拆分为开发、校准与独立外部验证集：

```bash
python ml/split_choice_sessions.py brow_preference_feedback.csv --output-dir ml/choice_splits
```

默认按顾客拆分为 60% 开发集、15% 校准集和 25% 外部验证集。它不会将同一顾客的不同会话放进不同数据集，也会拒绝缺少三款、出现多个最终选择或同一会话标签不一致的数据。若少数风格几乎没有被选择，脚本会拒绝不稳定的随机拆分，而不是偷偷制造标签。

再训练条件选择模型：

```bash
python ml/train_brow_choice_ranker.py ml/choice_splits/development.csv \
  --calibration-csv ml/choice_splits/calibration.csv \
  --external-validation-csv ml/choice_splits/external_validation.csv \
  --output app/src/main/assets/brow_choice_ranker.json
```

当前条件选择模型使用 39 个特征，其中新增四个特征是“用户明确选择的风格倾向 × 候选款式”交互项。它们使模型能够从真实反馈中学习：选择“偏柔和”的顾客是否更常选择柔和款，以及这种差异是否会随脸部几何特征变化。旧的 35 特征模型版本会被 Android 拒绝，不会误载入旧系数。缺少风格倾向的旧 CSV 默认记为“均衡自然”，新数据应保留应用导出的原始选项。

该模型在开发集拟合参数，只在校准集拟合 temperature scaling，并仅在外部验证集上评估最终表现。默认输出 release_approved=false。只有全部外部门槛通过并且专业人员检查样本质量、偏差和实际用途后，才可使用 --mark-reviewed-after-human-review 明确批准，随后重新构建 APK。APK 只加载通过这些门槛的模型资产。

模型目前的工程筛查门槛包括：外部验证至少 100 位不同顾客且至少 100 次完整选择会话，Top-1 准确率至少 0.40，优于现有几何基线的顾客级 bootstrap 95% 区间下界高于零，多分类 Brier 分数优于均匀选择基线，10-bin ECE 不高于 0.10，且 NLL 优于均匀选择基线。这些是项目的工程门槛，并非经过普适认可的行业标准，也不保证公平性或长期校准。按默认 60/15/25 比例，至少约 400 位不同顾客才能让外部验证集达到 100 位顾客。开发数据越多越好，且需要不同顾客而非同一顾客多次重拍充数。

## 当前完成状态与个人使用路径

应用侧现在保留两条不同的概率路径。

1. **经独立验证的条件选择模型**：从真实顾客同一次会话中对自然款、柔和款、立体款的最终选择学习。必须按匿名顾客拆分开发、校准与独立外部验证集，通过全部项目门槛并完成人工审核，才显示“本组选择概率”。三款概率归一化后合计为 100%。
2. **本机历史适配估计**：冷启动时不显示适配百分比。操作者可在“顾客偏好”中请顾客本人分别评价三款眉形的适配度，1 分为不适合，5 分为非常适合，并选择最终方案。新版记录为 schema v3。应用只使用已取得明确同意、保存在本机的 v3 适配标签，按面部几何、候选参数和风格倾向给历史案例加权，以 Beta(1,1) 平滑估计当前候选获得 4–5 分适配评价的概率，并显示近似 90% 区间。为避免将回头客重复计算成独立样本，每位匿名顾客只取最近一次完整三候选会话。至少要有 5 位不同匿名顾客，且每个候选的加权有效样本量不低于 2.5 才会显示。该模式属于基于本机真实反馈的小样本估计，尚未经独立外部校准，不能等同于通用、已验证的概率模型。

两个目标不应混淆。“获得 4–5 分适配度评价概率”是顾客可能给候选高适配评分的估计。“本组选择概率”是在当前展示的三款中最终被选中的概率，三项合计为 100%。任何一种都不保证纹绣治疗结果；冷启动或历史数据不足时，应用继续显示几何参考分或单独标识的群体整脸审美参考分，不编造适配百分比。

训练端 `ml/train_brow_ranker.py` 现在拒绝 v1/v2 或没有版本号的反馈行，避免将旧版“满意度”标签自动当成“眉形适配度”。收集新数据时，需导出使用新版应用、明确授权且由顾客本人评价适配度的 CSV。

## 开源模型审查结论

[ DAM-Net ](https://github.com/Dancingmader/DAM-Net) 可作为眉毛 matting/轮廓研究参考，但它没有“同一顾客选择哪一款眉形”的标签。[SCUT-FBP5500](https://github.com/HCIILAB/SCUT-FBP5500-Database-Release) 和 MEBeauty 是整脸审美/偏好数据，不是眉形候选选择数据。把这些整脸评分通过 softmax 转成百分比，会制造虚假的“适配概率”，因此应用将其限制为独立标识的参考分，不拿来替代顾客真实适配标签。

## 验证状态

当前仓库仍没有经真实顾客数据训练、独立校准并验证通过的通用模型资产。本机历史估计可随真实反馈积累而启用，但其区间仍受相似度尺度、评分者一致性和样本构成影响。要把结果报告为可靠的通用“真实适配概率”，仍需更多真实案例、顾客级隔离的校准/外部测试、评分一致性检查和分脸型/风格的偏差评估。合成标签、整脸审美分或同一顾客重复照片不能代替独立真实标签。
