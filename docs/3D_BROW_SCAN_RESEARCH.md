# 眉弓三维采集技术研究与实现路线

## 1. 研究结论

OPPO Find X7 已出现在 Google ARCore 官方支持设备列表的中国设备清单中，并标记为支持 Depth API：

- [ARCore 支持设备列表](https://developers.google.com/ar/devices/)，中国设备表中的 Oppo Find X7。
- [ARCore Depth API 概览](https://developers.google.com/ar/develop/depth)。
- [Android Depth API 开发指南](https://developers.google.com/ar/develop/java/depth/developer-guide)。
- [Android Raw Depth API 开发指南](https://developers.google.com/ar/develop/java/depth/raw-depth)。

这为本项目增加了一条比单张照片和 MediaPipe 相对 z 值更有依据的三维采集路线。ARCore Depth API 可以提供以毫米编码的深度图像，Raw Depth 还提供逐像素置信度。Depth API 不要求设备一定具有 ToF 硬件传感器，深度可以由设备运动估计，也可以融合设备具备的硬件深度传感器。

**设备支持 Depth API 不等于已经验证眉弓区域的测量精度。** 官方设备列表只能证明 API 兼容性，不能证明近距离眉弓扫描满足毫米级拓描要求。必须先在 Find X7 上做采集原型和实体标定。

## 2. 现有实现的边界

当前应用使用前置摄像头拍照，并用 MediaPipe Face Landmarker 提取面部关键点。MediaPipe 的相对 z 值不是毫米尺度的深度测量，不能直接用于计算眉弓的真实曲率。

因此，三维扫描应作为独立采集步骤，不应把现有前置拍照流程中的相对 z 值直接接入打印补偿。

建议的业务流程为：

1. 前置摄像头拍摄正脸，完成眉形设计和顾客确认。
2. 进入独立的三维采集页面，提示顾客保持头部和表情稳定。
3. 使用 ARCore 管理的相机采集多帧 RGB 与深度数据。
4. 通过 ARCore 相机内参和每帧相机位姿，将深度像素反投影到统一三维坐标系。
5. 根据面部关键点定位眉区，裁剪左右眉弓局部点云。
6. 评估深度置信度、点云覆盖率和重复扫描一致性。
7. 通过质量门槛后才允许计算局部曲率和模板补偿建议。

ARCore 扫描阶段与当前 CameraX 拍照阶段应分开管理，避免两个相机栈同时争用摄像头资源。

## 3. ARCore 深度采集的关键约束

### 3.1 设备与 API

应用启动扫描前应执行运行时能力检测：

- 检查 ARCore 服务是否可用。
- 检查当前设备是否支持 `Config.DepthMode.AUTOMATIC`。
- 检查深度模式是否能够成功启用。
- 优先测试 `acquireRawDepthImage16Bits()` 与 `acquireRawDepthConfidenceImage()`。
- 若 Raw Depth 不可用，可记录完整 Depth API 的可用性，但不得把两种数据质量视为相同。

不要仅通过设备型号字符串决定是否启用扫描。最终以 ARCore 运行时检测结果为准。

### 3.2 采集距离和运动

ARCore 官方资料指出，Depth API 依赖设备运动生成深度，通常在约 0.5 米至 5 米范围内效果较好。没有足够运动、没有可跟踪特征点或环境纹理不足时，深度可能暂时不可用或不准确。

眉弓是近距离小区域，本项目应先以约 0.5 米附近作为实验起点，记录实际可用深度覆盖率，不把它直接设为所有手机和所有环境的固定操作标准。扫描时让顾客保持静止，由操作者缓慢改变手机视角和位置。不要要求顾客主动转头来配合扫描。

### 3.3 深度值和置信度

ARCore Depth 图像使用 16 位深度值，深度值以毫米表示。Raw Depth 不是每个像素都有有效深度，置信度图用于筛除不可靠像素。官方建议优先使用高置信度的原始深度点。

深度值表示相机主轴方向的 z 深度，不是相机到该像素点的射线欧氏距离。若相机内参为 (f_x,f_y,c_x,c_y)，像素坐标为 ((u,v))，深度为 (z)，可按针孔模型反投影：

[
X=(u-c_x)z/f_x,qquad
Y=(v-c_y)z/f_y,qquad
Z=z.
]

实际实现必须使用与深度帧对应的相机内参、图像尺寸、方向和时间戳。不能把深度图像像素坐标直接当作照片像素坐标。

Raw Depth 可能存在空洞，并且并非每一帧都产生新的原始深度。应比较帧与深度图的时间戳，避免将重投影的旧深度误当成新的独立测量。

## 4. 眉弓局部曲面重建

建议第一版不追求完整人脸高精度网格，而是重建眉头至眉尾附近的局部曲面。

### 4.1 点云生成

每帧处理步骤：

1. 读取深度图和置信度图。
2. 按置信度阈值过滤无效深度点。
3. 使用相机内参将深度点反投影到相机坐标系。
4. 使用该帧 ARCore 相机位姿转换到扫描参考坐标系。
5. 将多帧有效点云进行配准和融合。
6. 根据人脸关键点及 RGB 图像确定眉区范围。

点云应保存采集设备型号、相机内参、扫描时间戳、深度帧时间戳、相机位姿、置信度阈值和采集质量信息，便于复现实验。

### 4.2 局部曲面拟合

在眉弓局部坐标系中，可先尝试二次曲面：

[
z=ax^2+bxy+cy^2+dx+ey+f.
]

由拟合曲面计算局部法向量和主曲率，得到横向与纵向的曲率描述。若点云覆盖不足、拟合残差过大或主曲率对采样变化敏感，则该次扫描应判为无效，不能强行输出补偿值。

二次曲面只是初始工程模型。后续应与三角网格局部曲面、独立三维扫描或可靠物理测量进行比较。

## 5. 二维眉形映射与打印补偿

推荐将二维设计曲线先映射到眉区三维曲面，再计算曲面上的实际路径长度。对每一眉区分别计算，不使用一个全脸统一缩放系数。

建议记录：

- 二维设计曲线长度。
- 三维曲面对应路径长度。
- 眉头、眉峰、眉尾在局部曲面上的三维坐标。
- 左右眉各分区的曲率和拟合误差。
- 三维映射前后的关键点距离变化。
- 展平后曲线长度和关键点位置误差。

局部补偿系数可定义为：

[
lambda_j=rac{L_{mathrm{surface},j}}{L_{mathrm{design},j}},
]

其中 (j) 表示眉头、眉身、眉峰或眉尾区域。该系数只有在三维点云质量通过门槛并经独立实体验证后，才允许进入打印计算。

三维曲面通常不能无失真地展平为二维平面。对于具有非零高斯曲率的曲面，展平时必须在曲线长度、关键点距离、角度和面积保真之间进行取舍。因此，打印模板应优先保持眉形路径长度和关键定位点，并使用柔性膜或分段结构适应剩余形变。

不得把单纯的 2D 图片缩放、MediaPipe 相对 z 值或未经验证的 ARCore 深度直接作为自动打印补偿依据。

## 6. 标定与验证实验

### 6.1 台架实验

先准备具有已知几何尺寸和不同曲率的三维头模，至少覆盖平缓、一般和较明显的眉弓曲面。使用独立三维扫描仪或可溯源测量工具作为参考。

每个头模重复扫描，比较：

- 深度有效点覆盖率。
- 局部曲面拟合残差。
- 曲率估计重复性。
- 眉头、眉峰、眉尾关键点误差。
- 曲面路径长度误差。
- 展平模板长度误差。
- 打印后 20 mm 校准框误差。

### 6.2 真人重复性实验

取得明确授权后，先开展小规模可行性研究，评估同一顾客多次扫描、不同操作者扫描以及不同光照和姿态下的结果差异。此阶段只研究测量重复性，不将补偿结果直接用于正式纹绣。

每位顾客的重复扫描应使用同一个匿名案例编号。开发集、校准集和独立验证集必须按顾客划分，不能按帧或按眉区记录随机拆分。

### 6.3 打印转印实验

每个打印模板都要记录打印机型号、驱动、纸张或膜材、缩放选项、20 mm 校准框实测值、眉区路径长度和拓描端点误差。

在独立顾客上验证后，才能决定是否启用某个区域的补偿方法。P10–P90 等统计区间只描述当前样本，不能自动解释为未来顾客的保证范围。

## 7. 第一轮开发任务

建议按以下顺序实现：

1. 建立 ARCore 最小测试页面，检测 Find X7 的 Depth API 支持情况。
2. 采集并可视化一帧 Depth、Raw Depth 和 Confidence 图像。
3. 实现多帧深度数据、相机位姿和内参导出。
4. 生成眉区局部点云并输出 PLY 文件供离线检查。
5. 实现局部二次曲面拟合和质量报告。
6. 在已知尺寸头模上完成重复性和误差测试。
7. 通过台架验证后，再将曲率补偿接入打印模板流程。

第一轮只输出三维扫描质量和曲率测量报告，不自动修改打印尺寸。只有通过独立验证后，才逐步开放个性化补偿。
