# 眉形设计助手（Android 原型）

本仓库是面向纹绣师的眉形设计、方案比较与打印辅助 Android 原型，优先针对 OPPO Find X7 验证。

## 当前功能

- 支持 CameraX 前置摄像头拍摄，也支持从相册/下载目录通过系统图片选择器导入照片。导入图在本机解码、处理 EXIF 方向并限制最大边长以控制内存，然后重新运行 MediaPipe Face Landmarker；照片不会上传服务器。为沿用当前自拍预览坐标约定，导入图会水平镜像后进入设计，最终打印时按现有模板流程翻回。
- 拍摄前显示顾客授权提示，检查照片中脸部大小、居中程度和头部倾斜。
- 生成自然款、柔和款和立体款候选。未安装训练模型时，用可解释的几何规则初排，参考分不是 AI 概率。
- 调整眉形粗细、长度和弧度，支持渐变预览、暂停、参数回撤、多方案保存、删除和对比。眉区人工补画/擦除现在支持整笔撤销与重做，避免一次误操作后只能重新分割。每套方案可保留其自身的原生眉区掩膜，避免对比时误用另一套方案的识别结果。
- 提供基础本机案例库，保存顾客案例名、匿名编号、照片、设计时的精确人脸关键点、当前掩膜与已保存方案。重新打开新格式案例时复用保存的关键点，避免因模型版本或再次推理让已保存眉形漂移；旧格式案例没有关键点时才尝试重新检测。案例照片、掩膜和包含关键点的案例索引使用 Android Keystore 管理的 AES-GCM 在本机加密，不上传服务器，保存前会提示本机留存授权，可在案例库打开和删除。新增用户明确授权的口令保护案例备份，采用 PBKDF2-HMAC-SHA256 派生 AES-GCM 口令密钥，在另一台设备导入时会使用新设备 Keystore 密钥重新加密。备份文件含可识别人脸的敏感内容，须独立保管文件与口令。忘记口令无法恢复，备份恢复功能仍需真机跨设备回归测试。
- 原生眉区预分割支持灵敏度调整、手工补画/擦除，并可切换“原生眉形轮廓底稿”模式，让已编辑掩膜直接驱动预览、对比、效果图和打印描线。构建流程会下载并打包 EasyPortrait 的轻量 BiSeNet 人脸解析 ONNX 模型（约 13.4 MB），经过公开人像分通道可视化，将当前导出模型的第 2、3 类用于左右眉区初始掩膜；该映射已修正，但仍需在专业标注的真实纹绣照片上做准确率验证，失败时回退到自适应对比度预分割。模型及其来源数据采用 EasyPortrait 作者说明的 CC BY-SA 变体许可，分发时需遵守具体许可条款及署名/相同方式共享要求。该模型是预分割底稿，仍需人工复核。
- 在取得单独授权后，可以导出原始照片做人工标注。仓库含标注工具、轻量分割模型训练脚本、分组验证和候选模型晋级门槛。构建时下载的 EasyPortrait BiSeNet 权重是通用人脸解析预训练模型，不是根据本应用客户数据训练出的专用眉毛模型。
- 将当前设计效果图保存到手机相册。
- 可将当前顾客已保存的多套眉形候选导出为本地多页 PDF 方案册，包含效果预览、参数、匿名案例编号和打印限制提示。导出前会提醒确认顾客对人脸效果图保存/分享的授权。方案册仅用于沟通留档，不是 1:1 拓描模板。
- 通过 Android 打印框架输出眉形轮廓稿，按实测瞳距初步换算物理尺寸，输出前将自拍预览的左右镜像翻回真实方向，并在打印页附 20 mm 校准框。打印比例校准按操作者填写的“打印机/纸张/驱动配置”分别保存，可根据上一张打印稿的实测方框尺寸迭代修正，避免不同配置共用一个全局系数。Android 打印服务不能保证应用获知最终选中的物理打印机，因此每次切换设备、纸张或设置仍需由操作者切换配置并重新实测校准框。修正值只补偿可重复的整体缩放，不代替真实尺寸测量。
- 录入左/右眉头、眉身、眉峰和眉尾的实测表面弧长与弦长，计算修正系数与局部圆弧近似半径，保存匿名记录并导出 CSV。只有当前匿名顾客八个区域都已实测时，才可选择把区域长度系数实验性地应用到打印轮廓。
- 新增实体转印误差闭环：可按命名打印配置、八个眉区和修正方法记录皮肤弧长、纸面模板路径长度、长度误差与端点定位误差，导出匿名 CSV，并用 `ml/analyze_stencil_transfer.py` 按顾客分组分析误差分布。它分开统计未修正与实测修正方案，避免对照组与处理组混算。分析只报告描述性统计或预先指定阈值的工程筛查，不自动改变任何校正系数。详见 [转印验证流程](docs/TRANSFER_VALIDATION_PROTOCOL.md)。
- 收集匿名顾客满意度和方案偏好，导出 CSV。提供按顾客案例分组的训练脚本，在真实数据积累后生成可由应用加载的 `brow_ranker.json`。
- 提供按匿名顾客分组的曲率区间分析、圆弧半径描述统计、bootstrap 置信区间脚本和 Python CI 测试。
- CI 使用同一套 MediaPipe 人脸关键点模型和 EasyPortrait ONNX 模型，对公开示例人像执行图像链路冒烟测试，输出眉区覆盖预览与 JSON 报告。该测试验证人脸检出、模型张量推理和应用中的类别映射/回退路径，不等同于专业标注集上的分割准确率。
- Android CI 除了构建 APK，还会在 Android 模拟器中安装并启动 Activity，检查启动后是否发生致命异常。这是安装/启动烟测，不是对触摸交互、相册选择、打印机或 OPPO Find X7 真机行为的完整验收。

## 运行与构建

每次推送到 `main` 分支都会触发 GitHub Actions。打开 **Actions → Build Android APK**，进入最新成功的工作流，下载 `face-pattern-oppo-debug-apk` 工件。

当前自用 APK 仅包含 `arm64-v8a` 原生库，以减小安装包体积，面向 OPPO Find X7 等 64 位 ARM Android 手机，不适用于 x86 模拟器或仅支持 32 位 ARM 的旧设备。

本地构建需要 JDK 17、Gradle 8.13、Android Gradle Plugin 8.13.0 和 Android SDK Platform 36，执行：

```bash
gradle --no-daemon assembleDebug
```

## 产品化状态

当前 PR 候选版本为 target API 36 的自用调试原型（0.9.5，versionCode 14）。PR 分支的 Android 构建、Python 自动测试和公开图片烟测已通过，新增的 UI 仪器测试正在由 GitHub Actions 验证。该版本增加了按顾客完全隔离的开发集、校准集和外部验证流程，报告概率校准指标，并要求新偏好模型优于现有几何规则基线且经过人工审核后才启用。曲率区间先按匿名顾客汇总重复测量。以上是代码与验证工具的完善，不等于已经拥有真实顾客训练的 AI 模型或已验证的三维曲率区间。真实数据、独立验证、OPPO Find X7 与目标打印机实测、运营者正式签名密钥和隐私政策审核仍是正式可靠使用的前置条件。
## 重要限制

1. 目前没有基于真实顾客反馈训练的排序模型文件，因此推荐仍基于几何启发式参考分，不是经校准的概率，也不应被描述为已验证的“最适合眉形”。必须先获得顾客授权，采集多个候选的满意度，再按 `ml/README.md` 训练并进行独立验证。
2. 应用能从原生眉区掩膜提取描线轮廓并支持人工补画/擦除。构建版本优先用 EasyPortrait BiSeNet 人脸解析的眉毛类别产生初始掩膜，如果模型缺失、运行失败或预测区域近乎为空，则退回自适应对比度算法。模型可能把眉妆、阴影或眉毛周边皮肤误识别，也可能漏掉浅色/稀疏眉毛，尚未完成独立准确率验证。输出必须由专业纹绣师确认，并遵守模型及数据许可中的署名和相同方式共享条件。
3. 单张正面照片不能唯一恢复眉弓真实三维曲率。MediaPipe 相对 z 已明确禁止进入实际打印几何，避免用未经标定的相对深度改变模板。顾客实测弧长/弦长系数仍只作为手动选择的实验性长度修正，且尚未证明转印误差改善。新增转印误差记录、CSV 导出和按打印配置/眉区分析脚本，但统计通过只允许人工审核，不会自动启用修正。
4. 1:1 输出依赖实测瞳距、拍摄透视、打印服务和打印机设置。必须打印后实测 20 mm 校准框，确认尺寸无误后再用于拓描。不同打印机的真实输出尚未全部验证。
5. 当前仍是调试原型，尚未完成 OPPO Find X7 真机全流程验证、门店可用性验证、独立 AI 模型验证、案件库长期使用测试或正式发布签名。不可将未经校验的打印稿直接用于不可逆纹绣操作。

## 曲率标定建议

完整测量方法、匿名编号、重复测量和验证建议见 [ml/CURVATURE_PROTOCOL.md](ml/CURVATURE_PROTOCOL.md)。


同一局部段需要同时测得皮肤表面弧长与两端直线弦长，修正系数定义为 `k = 表面弧长 / 直线弦长`。按左右眉头、眉身、眉峰、眉尾分区记录。样本 10%–90% 分位是当前测量样本的描述统计，不是保证适用于所有顾客的解剖边界。正式确定区间前，应建立统一测量协议、重复性评估和独立验证集。

## 隐私与安全

原型不把照片上传服务器。拍摄前会提示取得顾客同意，照片用于本机内存中的设计与打印。保存效果图会将含人脸的图片写入相册。匿名偏好和曲率记录保存在应用内，可导出 CSV，也可用应用内按钮清除。已导出的 CSV 和相册图片需要用户另行删除。案件库提供应用私有目录中的保存/打开/删除功能，照片、掩膜和案例索引使用 Android Keystore AES-GCM 加密，但尚未实现密码保护的跨设备导出、角色权限和自动备份。密钥不可随文件夹复制迁移。正式使用前仍要完成隐私告知、权限审查、安全评估、数据保留与删除政策审查。
